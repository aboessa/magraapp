# 05 — الإتقان والقياس

## الكتابة إلى `attempts`

كل مستوى مُنجز يكتب **سجلًا واحدًا**:

| الحقل | القيمة |
|---|---|
| `game_id` | معرف اللعبة |
| `episode_id` | معرف الحلقة إن كانت اللعبة مرتبطة بها، وإلا `NULL` |
| `score` | البنود الصحيحة **من أول محاولة** |
| `max_score` | عدد البنود |
| `answers` | JSON مختصر، **بلا أي بيانات شخصية** |
| `time_spent_seconds` | زمن فعلي، **لا يُعرض للطفل** |
| `help_used` | 1 عند تلميح أو تبسيط أو حل |

### مثال `answers`

```json
[
  { "item": "i1", "correct": true,  "attempts": 1 },
  { "item": "i2", "correct": true,  "attempts": 3 }
]
```

**ممنوع** في `answers`: اسم الطفل، تاريخ ميلاده، معرف جهازه، أي نص كتبه.

## قواعد `mastery`

يُحدَّث على **آخر 5 محاولات** لنفس `objective_id`:

| المستوى | الشرط |
|---|---|
| `not_started` | لا محاولات |
| `introduced` | محاولة واحدة على الأقل |
| `practicing` | دقة 50–79% |
| `assisted` | دقة ≥ 80% **مع** `help_used = 1` |
| `independent` | دقة ≥ 80% في 3 محاولات متتالية **بلا** مساعدة |
| `needs_review` | هبوط تحت 50% بعد `independent` |

`assisted` **ليس مستوى مُهينًا**؛ هو إشارة للنظام ليقترح تدريبًا، ولولي الأمر ليعرف موضع الحاجة.

## احتساب `score` لكل محرك

| المحرك | `score` | `max_score` |
|---|---|---|
| `match_pairs` | الأزواج الصحيحة من أول محاولة | عدد الأزواج |
| `trace_color` | المسارات المكتملة | عدد المسارات (التلوين لا يُحسب) |
| `sort_bins` | العناصر الصحيحة من أول محاولة | عدد العناصر |
| `memory_flip` | = `max_score` عند الإكمال | عدد الأزواج |
| `count_quantity` | البنود الصحيحة من أول محاولة | عدد البنود |
| `sequence_order` | 1 عند الترتيب الصحيح | 1 |
| `word_build` | الكلمات الصحيحة من أول محاولة | عدد الكلمات |
| `rhythm_tap` | النقرات الناجحة | إجمالي النوتات |
| `logic_pattern` | 1 للإجابة + 1 للتعليل | 1 أو 2 |
| `block_code` | 1 للوصول + 1 لـ`optimal_blocks` | 2 |
| `sim_lab` | 1 **للتفسير** فقط | 1 |
| `timeline_map` | العناصر الصحيحة من أول محاولة | عدد العناصر |

### ملاحظات مهمة

- **`sim_lab`**: التوقع الخاطئ **لا يُخصم**. التفسير وحده يُقاس.
- **`logic_pattern`**: الوصول إلى `independent` في المستويين 4 و5 يتطلب **تعليلًا صحيحًا**، لأن الإجابة الصحيحة بلا تعليل قد تكون تخمينًا.
- **`block_code`**: الحل الأطول **لا يُعاقب**؛ `optimal_blocks` مكافأة إضافية فقط.

## المحركات التي لا تُقاس

| المحرك | السبب | ما يُكتب |
|---|---|---|
| `memory_flip` (حزم متماثلة) | ترفيه أولًا | `attempts` فقط، بلا `mastery` |
| `rhythm_tap` | ترفيه أولًا | `attempts` فقط، بلا `mastery` |

المستوى 5 من `memory_flip` (أزواج مترابطة) **يمكن** ربطه بهدف مفردات إن رغب المحرر.

## التقدم عبر Durable Objects

اللعبة **لا تكتب في D1 مباشرة**.

```
POST /api/v1/family/progress
Authorization: Bearer <access_token>

{
  "child_id": "...",
  "content_type": "game",
  "content_id": "<game_id>",
  "event_id": "<uuid ثابت لكل محاولة>",
  "position_ms": 0,
  "duration_ms": 0,
  "completed": true,
  "score": 4,
  "max_score": 5,
  "answers": [ ... ],
  "time_spent": 42,
  "help_used": false
}
```

المسار:

```
FamilyDO (تحقق ملكية + idempotency + كتابة SQLite)
  → Outbox داخل نفس transaction
  → Alarm
  → Queue: family-events
  → Consumer
  → إسقاط D1 (للإدارة فقط)
```

### الضمانات المؤكدة

| الضمان | الحالة |
|---|---|
| إعادة إرسال نفس `event_id` لا تُكرّر المحاولة | ✅ محقَّق فعليًا |
| ملكية الطفل تُتحقق داخل `FamilyDO` من `parentId` الموثّق | ✅ محقَّق |
| الحدث لا يُفقد عند فشل إرسال Queue | ✅ Outbox داخل transaction |
| D1 ليست مصدر الحقيقة لحالة الأسرة | ✅ إسقاط للقراءة فقط |

## تقارير ولي الأمر

| مسموح | ممنوع |
|---|---|
| «يحتاج تدريبًا على التصنيف باللون» | «فشل 5 مرات» |
| «أتقن العدّ حتى 10» | «نسبة الخطأ 40%» |
| «جرّب 3 مرات وأكمل بمساعدة» | ترتيب مقارنة بأطفال آخرين |
| وقت اللعب الإجمالي | ضغط لزيادة وقت الشاشة |

## معايير القبول

- [ ] `attempts` تُكتب مرة واحدة لكل مستوى.
- [ ] `event_id` ثابت ويمنع التكرار عند إعادة الإرسال.
- [ ] `answers` بلا أي بيانات شخصية.
- [ ] `time_spent_seconds` لا يُعرض للطفل.
- [ ] `mastery` لا تُكتب للمحركات الترفيهية.
- [ ] تقرير ولي الأمر بلغة وصفية.
